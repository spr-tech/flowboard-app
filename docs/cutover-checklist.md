# Cutover checklist

Moving the live site from the old app (London database) to the rebuild (Frankfurt database). This is a fresh start: no data is copied. The plan and the reasons behind it are in [`plan/07-git-workflow.md`](plan/07-git-workflow.md#cutover-day).

Tick each box as you go. Don't start until `rebuild` is green in CI and has been checked on its preview.

## Before the day

- [ ] Decide the live domain (below, `https://<domain>`). It is the address in `APP_URL` and in the GitHub OAuth app.
- [ ] Create the **production GitHub OAuth app** (GitHub → Settings → Developer settings → OAuth Apps → New): homepage `https://<domain>`, callback `https://<domain>/api/auth/callback/github`. Keep it separate from the local and preview apps.
- [ ] Generate a **new** `AUTH_SECRET` for production: `pnpm dlx auth secret` (or `openssl rand -base64 33`). Never reuse the local or preview one.
- [ ] In Neon (Frankfurt project), check the **production** branch exists and is empty.

## Production environment variables (Vercel → Project → Settings → Environment Variables → Production)

| Variable             | Value                                                         | Where it comes from                                                                                         |
| -------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`       | Pooled connection string of the Frankfurt **production** branch | Neon → Frankfurt project → production branch → Connect, with "Connection pooling" on (host has `-pooler`). |
| `DIRECT_URL`         | Direct connection string of the same branch                   | Same dialog with pooling off. The running app doesn't read it; set it so Production matches the other environments. |
| `AUTH_SECRET`        | The new secret from "Before the day"                          | Generated by you.                                                                                           |
| `AUTH_GITHUB_ID`     | Client ID of the production OAuth app                         | GitHub → the production OAuth app.                                                                          |
| `AUTH_GITHUB_SECRET` | A client secret of the production OAuth app                   | Same page → "Generate a new client secret" (shown once).                                                   |
| `AUTH_TRUST_HOST`    | `true`                                                        | Fixed value. Auth.js trusts Vercel's host anyway; set it so every environment behaves the same.            |
| `EMAIL_USER`         | The Gmail address that sends Flowboard's email                | Your Gmail account.                                                                                         |
| `EMAIL_PASS`         | A Google App Password for that account                        | Google Account → Security → 2-Step Verification → App passwords. Make a new one named "Flowboard production". |
| `APP_URL`            | `https://<domain>` (no trailing slash)                        | The live domain. Email links, social cards, robots.txt and the sitemap use it.                              |

Vercel sets `VERCEL_ENV`, `VERCEL_PROJECT_PRODUCTION_URL` and `VERCEL_BRANCH_URL` itself; don't add them.

**Never set in Production:** `ALLOW_DB_RESET` (it only unlocks `db:seed` and `db:reset` on a laptop). Nothing else from a local `.env` is needed: the production build was checked with no `.env` at all.

**The old app's variables:** leave them in place during the rollback window, because a rollback runs the old code. The new app doesn't read them, except that Auth.js also reads `NEXTAUTH_URL` if it is set: make sure it is `https://<domain>` or delete it.

## On the day

- [ ] Copy the current Production `DATABASE_URL` (and `DIRECT_URL`, if set), the London ones, into a password manager. They are the rollback.
- [ ] Create the tables on the Frankfurt production branch from the `rebuild` checkout, giving the direct URL to this one command only (it overrides `.env`, so your laptop's `.env` keeps pointing at dev):
      `DIRECT_URL="<Frankfurt production direct URL>" pnpm prisma migrate deploy`
      Check the host it prints is the Frankfurt **production** branch. Never seed it.
- [ ] Set every Production variable in the table above. `DATABASE_URL` and `DIRECT_URL` replace the London values.
- [ ] Merge `rebuild` into `master` with a merge commit (not squash). Vercel builds and deploys Production.
- [ ] Test on `https://<domain>`:
  - [ ] the tab shows the Flowboard icon; `/robots.txt` and `/sitemap.xml` use `https://<domain>`
  - [ ] register a new account; sign out; sign in with email and password
  - [ ] sign in with GitHub
  - [ ] "Forgot password" email arrives and its link opens `https://<domain>/reset-password/...`
  - [ ] create a project, add a task, drag it to another column, reload: it stays
  - [ ] invite your `+tag` Gmail address; the link opens `https://<domain>/invite/...` and joins
  - [ ] an unknown address shows "We couldn't find that page"

## If something is wrong: roll back

1. Vercel → Deployments → the last deployment of the old app → "Instant Rollback".
2. Put the London `DATABASE_URL` (and `DIRECT_URL`) back in Production, then redeploy that old deployment so it reads them.
3. Check the old site signs in. Anything created in the new app stays in Frankfurt for the next attempt.

## A few weeks later, with no rollback

- [ ] Delete the old app's leftover Production variables (`NEXTAUTH_SECRET`, `NEXTAUTH_URL` and anything else the new app doesn't read).
- [ ] Delete the old London database, and its Neon account if nothing else uses it.
- [ ] Delete the old GitHub OAuth app if the old site had its own.
